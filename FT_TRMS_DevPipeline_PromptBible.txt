Cross-Cutting Development Standards 
Branching Strategy (Git Flow) 
main          ← production only; protected; requires PR + review 
develop       ← integration branch; all features merge here first 
feature/*     ← one branch per task (e.g. feature/trip-pause-resume) 
fix/*         ← bug fixes 
release/*     ← pre-release stabilization 
 
PR Rules: 
  - Minimum 1 reviewer approval required 
  - CI must pass (lint + typecheck + tests) 
  - No direct pushes to main or develop 
 
Commit Message Convention (Conventional Commits) 
Type Usage Example 
feat New feature feat(trips): add pause/resume endpoint 
fix Bug fix fix(auth): handle expired refresh token edge case 
chore Config / tooling chore: add eslint rule for no-console 
test Tests only test(claims): add approval workflow unit tests 
docs Documentation docs: update API endpoint table in README 
perf Performance perf(locations): batch insert 5 points per DB call 
security Security fix security(auth): add rate limit to login endpoint 
 
Definition of Done (Every Task) 
• Code written and self-reviewed (no console.log, no TODOs) 
• TypeScript: zero type errors (tsc --noEmit passes) 
• ESLint: zero warnings 
• Unit tests written for business logic functions 
• API changes reflected in Postman collection (shared team workspace) 
• PR description explains what changed and why 
• Reviewed and approved by at least one teammate

M2-A: Backend Auth Middleware — Prompt 
You are building the authentication and authorization layer for FT-TRMS. 
Tech: Node.js + Express + TypeScript + Supabase Auth + @supabase/supabase-js v2 
 
BUILD THE FOLLOWING FILES: 
 
1. src/config/supabase.ts 
   - Init Supabase client with SERVICE_ROLE_KEY (server-side only) 
   - Export: supabaseAdmin (uses service role key) 
   - Never expose service key to client 
 
2. src/middleware/authenticate.ts 
   - Express middleware that reads Authorization: Bearer <token> 
   - Calls supabaseAdmin.auth.getUser(token) to verify 
   - On success: fetches user record from users table (not just auth) 
   - Attaches to req.user = { id, email, role, full_name, rate_per_km } 
   - On failure: returns 401 { success: false, error: 'Unauthorized' } 
   - Handle edge cases: missing header, malformed token, revoked session 
 
3. src/middleware/requireRole.ts 
   - Factory: requireRole(...roles: UserRole[]) => RequestHandler 
   - Checks req.user.role is in allowed roles 
   - Returns 403 if not: { success: false, error: 'Insufficient permissions' } 
   - MUST be used AFTER authenticate middleware 
 
4. src/modules/auth/auth.router.ts 
   - POST /auth/login 
     Body: { email, password } 
     Action: supabase.auth.signInWithPassword() 
     Response: { access_token, refresh_token, user: { id, email, role, full_name } } 
   - POST /auth/refresh 
     Body: { refresh_token } 
     Action: supabase.auth.refreshSession() 
     Response: new { access_token, refresh_token } 
   - POST /auth/logout 
     Auth: required 
     Action: supabase.auth.signOut() 
   - GET /auth/me 
     Auth: required 
     Response: req.user object 
 
5. src/middleware/rateLimiter.ts 
   - Use express-rate-limit 
   - authLimiter: 5 attempts per 15 min per IP (for login route) 
   - apiLimiter: 200 requests per minute per IP (for all other routes) 
 
TYPES: Import UserRole, ApiResponse, AuthTokens from '@ft-trms/shared' 
ERROR HANDLING: All errors wrapped in try/catch; use a custom AppError class

M3-A: Backend Trip Service — Prompt 
You are building the Trip Service for FT-TRMS. 
Tech: Node.js + Express + TypeScript + node-postgres (pg) + Supabase 
 
TRIP STATE MACHINE: 
  STARTED → PAUSED → RESUMED → ENDED 
  STARTED → ENDED (no pause) 
  Any state → CANCELLED (admin only) 
  Invalid transitions must return 409 Conflict 
 
BUILD THE FOLLOWING: 
 
1. src/modules/trips/trip.service.ts 
   Functions: 
   - startTrip(employeeId, payload: StartTripSchema) 
     Creates trip record with status STARTED 
     Records start lat/lng as first LocationPoint 
     Returns trip with socket_room name ('trip:{id}') 
 
   - pauseTrip(tripId, employeeId) 
     Validates: trip exists, belongs to employee, status is STARTED|RESUMED 
     Updates: status=PAUSED, stores pause_start_at in Redis with key 'pause:{tripId}' 
 
   - resumeTrip(tripId, employeeId) 
     Validates: status is PAUSED 
     Gets pause_start_at from Redis 
     Updates: status=RESUMED, adds elapsed seconds to paused_duration_sec 
 
   - endTrip(tripId, employeeId) 
     Validates: status is STARTED|RESUMED|PAUSED 
     Calls calculateTripDistance(tripId) → sums Haversine segments 
     Updates: status=ENDED, total_distance_km, end_time 
     Calls ClaimService.autoCreateClaim(tripId) — MUST be atomic (transaction) 
 
   - calculateTripDistance(tripId): number 
     SELECT ordered location_points for trip 
     Apply Haversine between consecutive points 
     Skip points where is_anomaly=true 
     Return total km 
 
2. src/utils/haversine.ts 
   - haversine(a: {lat,lng}, b: {lat,lng}): number — returns km 
   - Must handle edge cases: same point → 0, antipodal points 
   - Export unit tests: write them in __tests__/haversine.test.ts 
 
3. src/modules/trips/trip.router.ts 
   POST   /trips/start         → authenticate, requireRole(EMPLOYEE) 
   POST   /trips/:id/pause     → authenticate, requireRole(EMPLOYEE) 
   POST   /trips/:id/resume    → authenticate, requireRole(EMPLOYEE) 
   POST   /trips/:id/end       → authenticate, requireRole(EMPLOYEE)

1. fraud.service.ts 
 
   interface ValidationResult { 
     valid: boolean; 
     anomalyReason?: AnomalyReason; 
     shouldStore: boolean;   // true even for anomalies (for audit trail) 
   } 
 
   validateLocationPoint(prev: LocationPoint | null, curr: IncomingPoint): 
   ValidationResult 
 
   Checks (in order): 
 
   a) FIRST POINT: if prev is null → always valid (no comparison possible) 
 
   b) ACCURACY CHECK: 
      if curr.accuracy_m > settings.max_accuracy_m (default 150) 
      → return { valid: false, anomalyReason: LOW_ACCURACY, shouldStore: false } 
      (don't store inaccurate points at all) 
 
   c) SPEED CHECK: 
      distKm = haversine(prev, curr) 
      timeSec = (curr.recorded_at - prev.recorded_at) / 1000 
      speedKmh = (distKm / timeSec) * 3600 
      if speedKmh > settings.max_speed_kmh (default 200) 
      → return { valid: false, anomalyReason: SPEED_ANOMALY, shouldStore: true } 
 
   d) TELEPORT CHECK: 
      if distKm > settings.max_jump_km (default 50) in one interval 
      → return { valid: false, anomalyReason: TELEPORT, shouldStore: true } 
 
   e) ALL CHECKS PASSED: 
      return { valid: true, shouldStore: true }
